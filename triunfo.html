Triunfo Fitness

Mobile ecosystem for personal trainers and students

Year2024
StackFlutter · Dart · Firebase · Provider
TypeMobile · Fitness
RoleFull Stack Developer
01Overview

The problem. Personal trainers were prescribing workouts over WhatsApp and spreadsheets — students lost track of plans mid-week, trainers had no visibility into adherence or progression, and personal records vanished into screenshots.

The solution. Triunfo is a two-sided mobile app that connects personal trainers to their students in real time.

Trainer side

What the trainer does

  • Creates periodizations and workout sheets with exercises, sets, load and rest time
  • Assesses students with anamnesis, body composition, anthropometric measurements and progress photos
  • Tracks each student's execution and progression in real time
  • Receives post-workout feedback with notes and comments
Student side

What the student does

  • Runs prescribed workouts set by set with built-in rest timer
  • Logs load, reps and effort level for each set
  • Sees exercise history with progression charts
  • Gets load suggestions based on previous sessions
  • Detects personal records automatically
  • Compares progress photos with a before/after slider

Data is synced via Firebase — the trainer can see the student's workout happening while they execute it.

02Architecture

Online-first by design. Firestore is the source of truth — the trainer sees the student's session unfolding in real time as it happens.

03Key features

Workout prescription

Trainers build programs by mesocycle — exercises, sets, target loads, RPE windows.

Real-time trainer view

Firestore listeners stream each set as the student logs it — the trainer watches the session unfold without polling or refresh.

Automatic PR detection

Personal records flagged in real time — by 1RM estimate, by volume, by tonnage.

Per-set RPE

Quick RPE input after each set — feeds into autoregulation and the trainer's adjustment loop.

Suggested progression

Next session's targets are computed from RPE and completion — no spreadsheet math.

Session check-in

Quick mood/energy/sleep input that contextualizes the session for the trainer's review.

Per-exercise history

Every set ever logged for an exercise, charted by load, volume, and PR markers.

Clean Architecture

Domain · data · presentation layers — business rules don't import Flutter or Firebase.

05Challenges
01

Real-time visibility for the trainer

The trainer needed to watch sessions unfold live — each set the student logged should appear immediately, without refresh, without polling, without burning quota on idle screens.

SolutionScoped Firestore snapshot listeners attached only to the active session document. The trainer's screen subscribes when the workout opens, unsubscribes when it closes — every write streams to the UI in real time with no manual sync.
02

Trainer ↔ student data conflicts

Two roles writing to the same workout: the trainer adjusts the plan, the student logs execution. Without clear ownership, edits would clobber each other.

SolutionDocument-level ownership: trainers own the prescription document, students own the execution document, joined by reference. No field is writable by both — conflict-free by structure.
03

PR detection with incomplete history

New users have no baseline — naive PR logic flagged every set as a record on day one, then went silent for weeks while it caught up.

SolutionDynamic baseline per exercise: PRs are relative to the available history with a confidence flag. Day-one sets are tracked but not celebrated; real PRs surface once the data is honest.
